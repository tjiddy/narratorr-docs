Everything narratorr-request connects to — narratorr itself and your notification channels — is
configured on the admin **Settings** page, not in environment variables. Values are **stored
encrypted at rest** (the at-rest key comes from `SETTINGS_KEY`, or is derived from
`SESSION_SECRET` when that's unset).

Each section has a **Test** button that validates the **current form values without saving** — so
you can confirm a connection is right before committing it.

## Public URL

Set this to where the app is reached (e.g. `https://requests.example.com`). It's used to
**deep-link notifications** back to the request queue / users page, so an admin can jump straight
from a ping to the thing that needs action. Leave it blank and notifications simply omit the link.

## Narratorr connection

The lifeline — required for search and requests to work. It's broken into discrete fields (the app
composes the base URL from them server-side):

| Field | Notes |
|-------|-------|
| **Host** | Hostname or IP only, **no protocol** (e.g. `narratorr` or `192.168.1.10`). |
| **Port** | Defaults to `3000`. |
| **Use SSL (https)** | Off = `http`, on = `https`. |
| **URL Base** | Optional — only if narratorr sits behind a reverse-proxy subpath (e.g. `/lib`). |
| **API key** | From **narratorr → Settings → API**. Masked once saved; leave blank to keep the current key. |

<Steps>

1. Enter the **Host**, **Port**, and **API key** (toggle **Use SSL** / set **URL Base** if needed).
2. Click **Test** — it validates the current values (using the stored key if you left the API key
   blank). Fix anything until it passes.
3. **Save settings.**

</Steps>

:::note[Internal hosts are expected here]
Unlike user-supplied cover URLs, the narratorr connection is trusted server-to-server admin
config, so internal/private hosts (`narratorr`, `localhost`, `10.x`, …) are intentionally
allowed — that's the normal sidecar setup.
:::

:::tip[Disconnecting]
There's no enable/disable toggle — narratorr is either configured or not. To disconnect, **blank
the Host and Save**; that clears the connection and its stored key.
:::

## Notification channels

Three optional channels. Toggle **Enabled** on a section to use it; each has its own **Test**
button. Remember these are **admin-facing** — they fire on a new request awaiting review and a new
user awaiting approval, not to the requester.

### ntfy

| Field | Notes |
|-------|-------|
| **Server URL** | Defaults to `https://ntfy.sh`; point at a self-hosted server if you run one. |
| **Topic** | The ntfy topic to publish to. |
| **Access token** | Optional — only for protected topics. Masked; leave blank to keep. |
| **Priority** | Optional — `min` / `low` / `default` / `high` / `max`, or `1`–`5`. |

### Email (SMTP)

| Field | Notes |
|-------|-------|
| **SMTP host** / **Port** | Port defaults to `587`. |
| **Implicit TLS (465)** | On = implicit TLS on 465; off = STARTTLS (e.g. 587). Toggling it nudges the port to match. |
| **Username** / **Password** | Optional for open relays. Password is masked; leave blank to keep. |
| **From** | Sender address. |
| **To (admin)** | Where admin notifications are sent. |

### Webhook / Discord

A single **Webhook URL**. POSTs a JSON payload to any endpoint, and works as a **Discord webhook
URL** out of the box.

## How secrets are handled

Secret fields (the narratorr API key, ntfy token, SMTP password) are **never returned to the
browser** — a saved secret shows as `•••••••• (unchanged)`. On save:

- **Leave a secret blank** → the stored value is kept.
- **Type a new value** → it replaces the stored one.
- **Clear it** → it's removed.

The **Test** button follows the same rule, so testing an existing connector with the secret left
blank uses the stored secret — you don't have to re-enter it just to test.
